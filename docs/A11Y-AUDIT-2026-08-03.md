# Accessibility & UX audit — snoomp frontend

**Scope:** `frontend/src/**` (7,072 lines: App.tsx, 7 components, dashboard.css) + `frontend/index.html`
**Tree state:** 2026-08-03, working tree (post-v0.2.1, includes uncommitted agent edits through 22:41)
**Method:** static source audit. The accesslint engine was unavailable and no dev server was running, so contrast and ΔE figures are computed from tokens — those are exact — while focus order, screen-reader output and reflow need live verification.
**Supersedes:** the a11y sections of `UI-REVIEW-2026-07-30.md`. Design-system findings there (Part 4, Part 6) still stand except where noted.

---

## Summary

**2 critical, 4 serious, 6 moderate** patterns after deduplication.

Most impactful:
1. **The WebSocket status pill is illegible in light mode** (1.93–3.16:1) — the newest feature is the least readable, and it's the one element that tells you monitoring stopped.
2. **Five interactive patterns are still non-semantic**, including monitor rows — the app's primary navigation remains keyboard-unreachable.
3. **No modal manages focus.** All four now announce as dialogs but none traps, restores, or inerts the background, so screen readers tab straight out into the page behind.

**This round closed the two worst outstanding items.** The hook-order crash is fixed in all four modals, and WebSocket reconnection is genuinely implemented — see Positive findings, which is a longer list than last time.

## Critical

### C1 — WebSocket status pill fails contrast in light mode

- **Pattern:** connection indicator uses hardcoded Tailwind-500 hexes on 12% tints, tuned for dark only
- **WCAG:** 1.4.3 Contrast (Minimum), AA
- **Affected:** `App.tsx:936–937` (colors), `:928–948` (pill)
- **Measured**, text on its own tint over the surface it sits on:

  | State | Dark | Light |
  |---|---|---|
  | `LIVE` `#22c55e` | 6.22 ✓ | **2.02** ✗ |
  | `RECONNECTING` `#f59e0b` | 6.55 ✓ | **1.93** ✗ |
  | `OFFLINE` `#ef4444` | 4.10 ✓ | **3.16** ✗ |

- **Fix:** drop the literals and use the existing per-theme tokens — `--color-up`, `--color-warning`, `--color-down` — which were already corrected for light in v0.2.1 (5.06 / 4.64 / 4.46). No new tokens needed.
- **Why critical:** this pill is the only signal that the dashboard has stopped receiving data. A monitoring tool silently showing stale "up" statuses is the failure mode the reconnect work was added to prevent; rendering the warning at 1.93:1 reintroduces it for every light-mode user. `RECONNECTING` — the state that most needs to be noticed — is the worst of the three.

### C2 — Primary navigation is not keyboard-operable

- **Pattern:** interactive controls built as `<div>` / `<span>` with `onClick`
- **WCAG:** 2.1.1 Keyboard (A), 4.1.2 Name, Role, Value (A)
- **Affected:**

  | Control | Location | Note |
  |---|---|---|
  | Monitor rows | `App.tsx:1273` | primary navigation; also now carries batch-select |
  | Filter chips | `App.tsx:1105`, `:1114`, `:1131`, `:1140` | **doubled** this round — group + environment rows |
  | Group headers | `App.tsx:1364` | collapse toggle |
  | Logo → home | `App.tsx:874` | |
  | Theme toggle | `App.tsx:963` | `title` only, no name, no `aria-pressed` |

- **Fix:** `<button type="button">` with the styling moved across; `aria-pressed` on chips and the theme toggle; `aria-expanded` + `aria-controls` on group headers; `<a href>` for the logo. Monitor rows in batch mode should be `role="option"` inside a `role="listbox"`, or a checkbox per row.
- **Why critical:** selecting a monitor is the app's core action and cannot be done without a mouse. The batch-select feature added this round inherits the same defect, so the newest workflow is also mouse-only.

## Serious

### S1 — No modal manages focus

- **WCAG:** 2.4.3 Focus Order (A), 2.1.2 No Keyboard Trap (A)
- **Affected:** `MonitorModal.tsx:426`, `UserPreferencesModal.tsx:126`, `BatchEditModal.tsx:103`, `App.tsx:2250`, `:2396`
- **Detail:** `role="dialog"` + `aria-modal` + `aria-labelledby` are now present on all four (good), and Escape works. But a repo-wide grep finds **zero** `focus()` calls, zero focus restore, and zero `inert`. `aria-modal="true"` tells AT the background is inaccessible while the DOM still allows Tab into it — the mismatch is worse than having neither.
- **Fix:** on open, move focus to the dialog; trap Tab within; on close, restore focus to the trigger; set `inert` on the app root; add `overscroll-behavior: contain`.

### S2 — No status messages are announced

- **WCAG:** 4.1.3 Status Messages (AA)
- **Affected:** zero `aria-live` / `role="status"` / `role="alert"` in 7,072 lines. Specifically `App.tsx:928` (connection state changes silently), auth errors, copy-to-clipboard confirmation, `MonitorModal` test-connection result, all loading states.
- **Fix:** `aria-live="polite"` on the status pill and result banners; `role="alert"` for auth failure with focus moved to it.
- **Note:** the connection pill changing from `LIVE` to `OFFLINE` with no announcement is the same failure as C1 for a different user group.

### S3 — Form labels are not associated

- **WCAG:** 1.3.1 (A), 3.3.2 (A), 4.1.2 (A)
- **Affected:** `htmlFor` appears **twice** in the entire codebase, both in `MonitorModal.tsx`. Every other field across App.tsx, UserPreferencesModal, BatchEditModal and the login form uses a bare `<label>` next to a bare `<input>`.
- **Fix:** a `<Field>` wrapper that generates an id via `useId()` and wires both. Retrofitting one primitive fixes ~40 fields at once.

### S4 — 12 blocking `alert()` calls carry all error and success feedback

- **WCAG:** 3.3.1 Error Identification (A), 3.3.3 Error Suggestion (AA)
- **Affected:** `App.tsx` ×8, `MonitorModal.tsx` ×2, `UserPreferencesModal.tsx` ×2
- **Fix:** a live-region toast. Several messages also state only the problem, not the next step — WCAG 3.3.3 wants both.

## Moderate / Minor

- **1.4.11 Non-text Contrast** — dark `--border` composites to **1.16:1** (needs 3:1). Light was raised to 12% this round and now reaches 1.31:1 — better, still short. Dark surface ladder is unchanged at 1.03 / 1.05 / 1.07; light was rebuilt on Slate and improved to 1.13 / 1.05 / 1.05.
- **1.4.3** — dark `--color-off` `#484f58` remains **2.34:1**, the last token failing outright. Light was fixed to 4.39:1 this round.
- **4.1.2** — one icon-only button lacks a name: `BatchEditModal.tsx:135`. Down from ~12 last audit.
- **2.5.8 Target Size** — accent swatches 13×13px (`App.tsx`), several icon buttons ~22×22px, custom scrollbar thumb 4px. Minimum 24×24.
- **1.4.10 Reflow** — still one layout media query in 1,747 lines. `.app-layout` is `width: 100vw` with a fixed 280px sidebar; at 320px the sidebar consumes the viewport. Straight AA failure.
- **Light-mode invisibility** — 48 hardcoded `rgba(255,255,255,0.02–0.05)` backgrounds remain (App 11, MonitorModal 8, BatchEditModal 2, UserPreferencesModal 2, PublicStatusPage 1, CSS 24). Each is white-on-white in light mode. Two chart `CartesianGrid` strokes are likewise white on white. Three emoji still carry status meaning.
- **Animation** — `transition: all` ×7 in `dashboard.css`. The `prefers-reduced-motion` block added in v0.2.1 is correct and covers the infinite animations.

## React & performance (Vercel rules)

Two CRITICAL-tier items from the prior review were resolved this round; the rest are unchanged or newly worsened by growth.

**Resolved ✓**
- `client-swr-dedup` / request amplification — `App.tsx:427–433` adds a 1,500 ms debounce on `fetchStatsAndIncidents`, replacing the per-message call. The ~100-requests-per-cycle problem is gone.
- Connection resilience — `App.tsx:436–511` implements reconnect with exponential backoff (1 s → 30 s cap), delay reset on `onopen`, `onerror` → `close()` → `onclose` retry, an `isMounted` guard, and timeout cleanup on unmount. This is a correct implementation, not a token one.

**Open, and larger than before**
- `rerender-memo` — `App.tsx` is now **2,623 lines with 54 hooks in one component**, up from 2,085/~30. Repo-wide there is exactly **one** `useMemo` (`BatchEditModal.tsx:45`) and **zero** `React.memo`, `useCallback` or `lazy()`. Every WebSocket frame still re-renders the navbar, both filter rows, every monitor row and its 20–30 heartbeat bars, all four modals and both charts. Extract and memoize `MonitorRow` on `id`/`status`/`response_time_ms` first — highest return for least risk.
- `bundle-dynamic-imports` — `recharts` (~150 KB gz) plus four modals are still statically imported, so they all ship in the bundle that renders the login screen. `BatchEditModal` adds to this. `React.lazy` the modals and chart sections.
- `bundle-barrel-imports` — icons still pulled from the `lucide-react` barrel across five files.
- `rendering-content-visibility` — sidebar and Infrastructure Overview still map unbounded arrays; each row renders 20–30 heartbeat divs.
- `js-cache-storage` — `localStorage.getItem` still in `useState(...)` argument position in several places, executing every render.
- `rerender-no-inline-components` — the sidebar list is still an IIFE inside JSX rebuilding the grouping pass on every render. `useMemo` on `monitors`/`groupBy`/`searchTerm`/both tag filters.
- `client-localstorage-schema` — the `snoomp_*` key set keeps growing, still unversioned.
- **URL state** — `view`, `selectedMonitor`, both tag filters, `searchTerm`, `groupBy` and now `isBatchMode` are all `useState`. No deep links, no back button, no shareable link to a failing monitor. Adopting a router also gives `bundle-preload` a natural home.

## Recommendations

**Architectural**
1. Four primitives remove most of this report: `<Field>` (`useId` + `htmlFor`, fixes S3 wholesale), `<Dialog>` (focus trap/restore/inert on top of the existing correct ARIA, fixes S1), `<Toast>` (live region, fixes S2 and S4), `<IconButton>` (required `label` prop, prevents C2/S-class regressions).
2. **Ban hardcoded colors in JSX.** C1 and the 48 white-alpha literals share one root cause. A lint rule rejecting hex and `rgba()` in `style={{}}` would have caught the status pill before it shipped.
3. **Split `App.tsx`.** At 2,623 lines and 54 hooks it is why memoization hasn't happened and why every socket frame repaints the world.
4. **Add `eslint-plugin-jsx-a11y` and `eslint-plugin-react-hooks` to CI.** The former catches C2, S3 and the icon-button class mechanically — roughly 60% of this report. The latter catches the class of crash fixed this round.
5. **Adopt a router**, which resolves the URL-state gap and enables route-level code splitting.

**Verify manually**
- Keyboard pass: logo → nav → sidebar → monitor row → detail actions. Expect failure at the sidebar.
- Screen reader on the monitor detail view — whether heartbeat and gauge state is conveyed at all.
- Open each modal and press Tab repeatedly; confirm whether focus escapes to the background.
- Light mode at 200% zoom and 320px width.
- Windows High Contrast — the `box-shadow`-based focus rings will vanish.
- Text over the translucent `--bg-card` and `rgba()` panels, which composite differently than the flat tokens measured here.

## Positive findings

Substantially more than the last audit, and worth stating plainly.

- **The hook-order crash is fixed correctly in all four modals.** `MonitorModal` (last hook 405, guard 415), `UserPreferencesModal` (83 / 92), `BatchEditModal` (45 / 88) — every guard now sits below every hook. This was an app-breaking bug and the fix is right, not patched around.
- **The WebSocket reconnect is a genuinely good implementation** — exponential backoff with a sensible cap, delay reset on success, mount guard, and full cleanup. It does what the changelog claimed.
- **Debouncing the stats refetch** is the correct fix for the amplification problem rather than a workaround.
- **All four modals now carry `role="dialog"`, `aria-modal` and `aria-labelledby`**, and Escape works everywhere. The ARIA that exists is correct — it just needs focus management behind it.
- **Icon-only buttons went from ~12 unnamed to 1.**
- **The light palette was rebuilt on Slate** and is materially better: `--text-muted` 7.24:1, `--color-off` 4.39:1, borders raised to 12%.
- **`prefers-reduced-motion`** block is correct and complete.
- **`font-variant-numeric: tabular-nums`** discipline is maintained across the new code.
- **`:focus-visible`** rings (not `:focus`) with a two-layer offset — still right.
- **Empty states remain well written**, explaining what is missing and what to do.

## Suggested order

1. **C1** — swap three literals for existing tokens. Minutes, and it restores the feature that matters most.
2. **`BatchEditModal.tsx:135`** aria-label; dark `--color-off`; dark `--border` to 12%.
3. **C2** — five control patterns to `<button>`. Restores keyboard operation of the whole app.
4. **S1** — focus management into a `<Dialog>` primitive; the ARIA is already correct.
5. **S3 + S4** — `<Field>` and `<Toast>` primitives.
6. **Lint gates** so none of the above regresses.
7. **React work** — extract and memoize `MonitorRow`, then lazy-load modals and charts, then router + URL state.
